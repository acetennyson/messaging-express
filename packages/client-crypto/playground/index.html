client-crypto playground

A developer playground for the end-to-end encryption package. Top: a guided tour that talks to a server (a built-in mock or yours). Below: a lab for the raw primitives. Yellow boxes show what a server can see.

Start here: connect, then follow the tour

This page plays three people (Alice, Bob and Eve, a stranger) who each run client-crypto in their own "device". Follow the numbered steps top to bottom. Every step says what it does, runs real package code, and tells you what you should see. The panel on the right is a live log of every HTTP request the package makes (secrets never appear in it: step 2 proves that). Rows for the step you just ran are highlighted.
Never paste a production secret. The ids default to the local test project used by the soak scripts; use your own if different. Steps that need POST /conversations with a client-chosen id (5 to 9) work on the real server once server stage 7.10 is in; until then they stop with a clear message and the rest still runs.

4. Backup and recovery

Alice's private key is encrypted under a key derived from her passphrase with Argon2id. The server stores the blob and the parameters, and cannot read it. The demo uses small parameters so it is quick; the real default is 19 MiB, 2 passes.

5. Key store (IndexedDB in this browser)

Where a real device keeps its private key and conversation keys. Unlike everything above, this survives a reload: save, reload the page, list. Keys are namespaced per server and per account, so two accounts on one browser never see each other's keys.

6. Attachments

A file is encrypted in 64 KiB chunks as it is read, so memory stays small however big it is. Its key, real name, type and size travel inside the encrypted message; the server only gets opaque bytes.
